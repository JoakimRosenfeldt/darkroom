Feature parity audit

Darkroom is a real local editor, but it is not close to full Lightroom parity.

The app already supports useful local browsing, culling, non-destructive edits, manual masks, Subject/Sky selection, and batch export. The large gaps are library intelligence, broad RAW and color fidelity, complete Develop tools, batch editing, and the cloud/mobile ecosystem.

Primary target: Lightroom desktop/cloud Classic-only gaps tagged separately Source audit + live UI walkthrough 18/18 repository tests passed
Bottom line

Darkroom is best described as a focused, local-first photo browser and early non-destructive editor. Calling it a Lightroom replacement today would overstate the catalog, search, metadata, RAW pipeline, editing, automation, sharing, and output capabilities.

Strongest area
Focused local workflow

One folder, fast grids, flags/ratings/labels, album grouping, crop, core tone/color, masks, and export.

Largest desktop gap
DAM and batch workflow

No photo search, keywords, smart albums, stacks, metadata editing, presets, copy/paste settings, or batch Develop.

Largest pixel gap
RAW and color engine

NEF-only RAW registration, 8-bit rendering/export, no camera/lens profiles, no color management, and embedded-preview fallback.

Largest literal parity gap
Adobe ecosystem

No cloud originals, mobile/web apps, shared albums, collaboration, community, Photoshop handoff, or Classic output modules.

Scope

Primary benchmark
Lightroom desktop and cloud library

This is the closest product comparison: desktop editing, local/cloud photo access, albums, search, AI, export, sync, and sharing.

Broader parity boundary
Classic, mobile, and web are explicit add-ons

Classic-only workflows such as tethering, Print, Book, Map, Web, Publish Services, and plug-ins are tagged. Mobile/web-only and ecosystem features are tagged too.

Why the distinction matters: Adobe sells two materially different desktop products under the Lightroom family. Lightroom is cloud-oriented across desktop, mobile, and web. Lightroom Classic is catalog-first and desktop-focused. Literal “full Lightroom parity” therefore combines a RAW editor, a digital asset manager, a cloud platform, mobile clients, and several pro output modules.

What works today

Library and culling

Recursive folder scan, folder tree, fixed and justified virtualized grids, multi-selection, keyboard navigation, picks/rejects, 0–5 stars, five labels, manual albums, and archive.

Core Develop

Exposure, contrast, highlights, shadows, whites, blacks, temperature, tint, vibrance, saturation, RGB/channel curves, eight-band HSL, sharpening, noise reduction, vignette, and grain.

Crop and geometry

Free and preset ratios, custom ratio, interactive handles, angle, heuristic auto-straighten, perspective X/Y, and distortion.

Masks

Brush, linear, and radial masks with add/subtract components, invert, enable/disable, duplicate, reorder, and local basic adjustments.

Local AI

Subject and Sky masks can run locally after an explicit model download. Models are cached and hash-verified, with WebGPU/WASM fallback.

Export and safety

Batch JPEG, PNG, WebP, AVIF, and TIFF; resizing, quality, lossless WebP, collision choices, progress/cancel, and recoverable source deletion through system Trash.

Distinct product strength: Darkroom works without an Adobe account, keeps originals local, and can keep AI inference local after model download. That is not parity with cloud Lightroom, but it can be a deliberate product advantage.

Material differences

These are the cases where a similarly named feature exists but behaves differently enough that it should not be counted as parity.

AreaDarkroom todayLightroom behavior and impact
Library modelOne active local root, scanned in place, with a per-root JSON catalog.Cloud Lightroom can hold originals in an account-backed library across devices; Classic supports full catalog workflows. A folder picker is not catalog or cloud parity.
RAW pipelineRegistered input profiles are standard images and NEF. LibRaw is configured for 8-bit output; NEF can fall back to an embedded JPEG preview.Adobe Camera Raw supports broad camera/lens matrices, camera profiles, high-bit processing, and color-managed output. Matching slider names does not produce matching pixels.
“Capture date” sortThe visible option sorts filesystem modification time.Lightroom sorts and filters on capture metadata. Darkroom’s label is currently inaccurate and can change ordering after file copies or edits.
Filmstrip scopeThe photo route rebuilds the filmstrip from every catalog entry, sorted by filename.Lightroom filmstrips follow the active source/filter. Darkroom can move from an album into unrelated or archived photos.
Archive and restoreArchive also removes album membership. Restore only clears the archive flag.A restore does not reconstruct the prior organizational state. This is narrower than a reversible catalog operation.
Before/originalHolding \ temporarily shows the original.Lightroom also provides split/side-by-side Before/After and Reference views. Darkroom’s quick check is useful, but not a comparison workspace.
HistoryUndo/redo is session memory, capped at 100 entries. Final settings persist; the history does not.Classic has a persistent History panel and Snapshots; cloud Lightroom has Versions. Restarting Darkroom loses the edit journey.
AI masksSubject and Sky use downloaded local models. Source prep caps at 2,048 px, then models run at 512×512 and 384×384.Adobe offers more selectors and cross-surface AI status. Darkroom has better offline privacy, but narrower selectors and lower model input resolution.
XMPUses familiar Adobe-named properties for a subset of settings and stores masks in proprietary darkroom:MaskingData. Pick/reject is catalog-only.Values can look interoperable while rendering differently. Mask data and the full curation state do not round-trip as Lightroom equivalents.
ExportStrong web-format breadth, but pixels leave WebGL as 8-bit RGBA, alpha is removed, and metadata is not injected. Output is capped at 50 MP.Lightroom has color-space, bit-depth, PPI, sharpening, watermark, metadata, DNG/original, preset, and Content Credential workflows.
Delete from diskFiles move to system Trash sequentially. A later failure can leave earlier files trashed while all catalog entries remain.The action is recoverable but not transactional. A batch can end with catalog and filesystem state out of sync.
PlatformsElectron packaging includes macOS arm64, Windows x64, and Linux x64 targets. Browser mode cannot do native import/export/AI.Lightroom desktop supports macOS/Windows and adds full mobile/web clients. Linux targeting is a Darkroom distinction, not cross-device parity.

What is missing for parity

The order below is about dependency and product coherence, not calendar estimates.

CORE 1

Build a real library and finding model

  • Search by filename, metadata, keyword, camera, lens, date, location, rating, flag, and edited state.
  • Keywords, captions, copyright, GPS, capture-time edits, smart albums, stacks, nested containers, duplicate detection, and scope-preserving viewer navigation.
  • Incremental watching, relink tooling, safer catalog reset, and explicit multi-root/catalog decisions.
CORE 2

Raise the RAW and color foundation

  • Broad camera RAW and format support, camera profiles, lens profiles, chromatic-aberration correction, defringe, and raw defaults.
  • High-bit, color-managed rendering and export, reliable full-resolution decode, histogram/clipping, HDR path, and output profiles.
  • Pixel and metadata validation against supported cameras, not only control-level parity.
CORE 3

Complete the daily Develop workflow

  • Texture, Clarity, Dehaze, Point Color, B&W, Color Grading, Calibration, Transform/Upright, rotate/flip, heal/clone/remove, red-eye, and Lens Blur.
  • Presets and profiles, copy/paste settings, sync/auto-sync, batch Develop, persistent history, snapshots/versions, virtual copies, full Before/After, and Reference view.
  • Range masks and Background/Object/People/Landscape selection with broader local controls.
CORE 4

Finish professional import and export

  • Card/camera import, Copy/Move/Add/Copy-as-DNG, duplicate checks, file naming, destination rules, metadata/keyword presets, and cancelable background work.
  • Export color space, bit depth, PPI, output sharpening, watermarks, metadata/privacy choices, filename templates, presets, original/DNG output, and transactional error handling.
FULL

Add the ecosystem and Classic-only surface area

  • Cloud originals, automatic backup, mobile/web apps, cross-device edits, shared albums, contributor/editor roles, comments, community, and learning.
  • Tethering, Photoshop/external-editor handoff, plug-in SDK, Publish Services, Print, Book, Slideshow, Map, Web galleries, HDR/panorama merge, and video.

Recommended parity boundary

Do not use literal full parity as the first product target. It would commit Darkroom to rebuilding three products at once: a professional RAW/DAM desktop app, a cloud collaboration platform, and a mobile/web ecosystem.
Practical target
Local-first Lightroom desktop core

Define parity around local photo management, broad RAW/color quality, complete editing, masks, presets, batch workflow, metadata, and professional export. Keep account-free and local AI as intentional differences.

Explicit exclusions
Defer the service and module perimeter

Cloud originals, social/community, mobile capture, shared editing, Print/Book/Map/Web, tethering, and plug-ins should be separate roadmap decisions, not hidden inside one “Lightroom parity” checkbox.

The smallest credible parity milestone is not “more sliders.” It is a coherent loop: import or link, find, cull, edit accurately, apply edits in batches, preserve metadata, and export predictably.

Method and limits

Darkroom evidence
  • Source audit across app/, components/, electron/, hooks/, lib/, stores/, tests, and packaging.
  • Live walkthrough at 1280×800 with the seven bundled demo photos. Electron filesystem calls were mocked at the browser boundary; native IPC paths were source-audited.
  • Library, viewer, Light, Color, Detail, Crop, Masking, and Export surfaces were inspected.
  • npm test: 18 passed, 0 failed.
Lightroom evidence
  • Official Adobe documentation only, checked on 23 August 2026.
  • Primary baseline: Lightroom desktop 9.4 and current cloud workflows. Lightroom Classic 15.4, mobile, and web are separately scoped.
  • Newer workflow pages and release notes take precedence where Adobe’s March 2026 comparison table is stale.
  • No paid Adobe instance was manually exercised; Lightroom behavior is based on Adobe’s published feature contract.
Not measured: pixel-level color accuracy, export colorimetric accuracy, a complete camera matrix, 100k-photo catalog performance, screen-reader conformance, long-running sync failure behavior, or private Nikon helper output. Those need dedicated verification, not inference from source structure.
