Leading words

These words carry one meaning throughout the runbook.

Gate

The observable condition that ends a step. Evidence must cover every listed clause.

Head

The current revision published by the app-owned manifest. It is the edit authority.

Projection

The original entry's XMP copy of a committed Head. It can diverge and requires reconciliation.

Receipt

The durable per-target record for a batch. It drives resume, retry, summary, and safe undo.

Each step contains the work every run needs. Branch rules stay beside their reference contract, so the main sequence remains readable.

Reference B. Persistence, migration, XMP, and recovery

Commit order

  1. Validate the proposed document and expected parent revision.
  2. Write and validate missing content-addressed assets.
  3. Write and validate immutable revision metadata.
  4. Atomically replace the app-owned manifest to advance the Head. This is the commit point.
  5. For the original entry, atomically write the Head to XMP as a Projection.
  6. Atomically record projected revision ID and digest in the manifest without changing the Head.

Load and conflict rules

  • Trust a manifest Head only when its revision, checkpoint chain, assets, and state hash validate.
  • Keep orphan immutable files for later idempotent collection.
  • Compare XMP digest with the last projection record. Mtime is evidence, not authority.
  • A clear external XMP change becomes one new revision.
  • Concurrent app and XMP changes show Keep Darkroom, Import XMP, Inspect differences, and Preserve both as virtual copy.

Catalog v2 migration

  1. Read and validate v2 without mutation.
  2. Create one source and one original entry for every current ID. Preserve the original ID.
  3. Put the current Develop document in the default version's root checkpoint. Invent no history.
  4. Rename decoder identity to decoderProfileId. Set camera profile to neutral unless an explicit supported selection exists.
  5. Resolve current XMP before publication. Stop for a conflict when app and XMP both changed.
  6. Write v3 through temporary replacement, reopen, validate, and retain a v2 backup through one successful restart.

Reference E. Camera profiles and default creation 
interface PixelProvenance {
  decoderPath: "libraw" | "nikon-sdk" | "embedded-preview" | "processed-standard";
  colorSpace: string | "unknown";
  transfer: "linear" | "encoded" | "unknown";
  bitDepth: number | null;

    | { kind: "available"; stage: "before-develop-tone" }
    | { kind: "unavailable"; reason: string };
}

Profile branch

  • A compatible branch applies one supported non-neutral transform before Develop tone work in both preview and export.
  • An unavailable branch records the decoder reason and uses neutral. It leaves #84 incomplete.
  • An embedded processed preview always takes the unavailable branch for camera-space transforms.
  • Imported files live in app-owned, content-hashed storage. Registry records selected ID and revision, compatibility, version, capabilities, parse errors, and unsupported opcodes.

Default creation branch

  1. Existing app document or accepted source XMP returns immediately. Defaults never run during normal hydration.
  2. New document reads minimum normalized camera, decoder, profile, and ISO facts.
  3. Priority wins first. Ties use camera and profile specificity, narrower inclusive ISO range, then stable rule ID.
  4. Unknown camera or ISO matches only an explicit unknown fallback.
  5. The winning preset payload creates the initial document and records rule ID and revision.
  6. Compare-and-set installs it only when no document exists.

  • Every target starts queued and ends in exactly one terminal state.
  • A Develop Receipt stores operation ID, frozen target, expected revision, before revision, after revision, and terminal result.
  • Persist the Receipt after every terminal result. Retry unresolved or retryable items only.

  • Export warnings decorate completed rows. They never form another terminal state.
  • Export cancellation stops new scheduling and lets active native encode report its real result.
