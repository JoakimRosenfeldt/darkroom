Originals

Read only

Never modify embedded EXIF, IPTC, XMP, pixels, or RAW container data. Darkroom may write its catalog, cache, journals, backups, XMP sidecars, and exported copies.

Durable owner

Electron

Parsing, catalog mutation, XMP publication, jobs, and restart recovery live behind validated preload APIs. React and Zustand hold projections and drafts.

Viewer context

One query

The grid, filmstrip, Previous and Next, return state, Before/After, and Reference View consume the same ordered asset IDs.

Hard boundaries

  • Keep the current single-root product and per-root JSON catalog. Do not introduce SQLite, multi-root catalogs, cloud sync, rename tracking, or original-file metadata writes.
  • Use an opaque AssetId at domain boundaries. It may wrap the current path-derived ID until a separate stable-ID foundation exists.
  • Keep raw parser records, XML documents, and filesystem paths behind adapters. UI and domain callers receive typed values and explicit availability states.
  • Search and facets are required scope. Issues #44, #45, and #46 require normalized metadata to affect search, filtering, sorting, and batch results.
  • Reference images are excluded from mutation command targets at the domain boundary. Visual focus alone never chooses a write target.

Domain rules

  • Source facts record what the file contains. They never create sidecar write intent.
  • Catalog intent contains only user-owned overrides, curation, Develop, presets, and pending removal of fields Darkroom previously owned.
  • Effective values resolve typed override first, then source. Display strings do not become storage or query keys.
  • Capture time stores camera wall time and optional offset separately. Never infer an unknown offset from the current computer.
  • Cache identity uses source SHA-256 plus parser and adapter versions. Size and mtime are scheduling hints and diagnostics.
  • Incomplete journals and their backups are never pruned. Unreferenced backups from completed operations default to 30-day retention until a documented policy replaces it.

XMP ownership, mapping, and reconciliation

Read this entire section before Steps 4 through 6. Step 0 freezes the exact v1 mappings. These rules define what may be written and when.

Extraction and precedence

Source extraction

  • Use the standard-image parser selected by G0.1. Use Sharp header metadata for structural facts and fallback diagnostics, not as a second semantic parser.
  • Prioritize active, selected, and visible entries. Backfill the rest after first grid paint in a bounded queue.
  • Cap XMP and decompressed metadata at 16 MiB unless Step 0 records a different accepted bound.
  • Parser failure records a warning and leaves the image viewable.

Field precedence

  • Structural facts come from the container. Capture facts use the richest RAW or EXIF claim and retain alternatives.
  • Embedded descriptive precedence is XMP, then IPTC, then EXIF description or artist. Keep all source claims inspectable.
  • Capture time uses DateTimeOriginal first, then frozen fallbacks. Store wall time and optional offset separately.
  • GPS stores signed decimal degrees, optional altitude, and source precision.

Sidecar publication safety. Portable filesystems do not provide a content-aware atomic replacement against an uncooperative external editor. Serialize Darkroom writers, hash immediately before replacement, copy exact prior bytes, recheck, publish with the platform's accepted atomic primitive, and read back. Reset-to-source rule. Remove the catalog override. Remove a sidecar field only when the baseline says Darkroom owns it. If the sidecar changed after the baseline, reset creates a conflict and removes nothing. Preserve fields Darkroom never owned unless the user explicitly adopts or clears them.

Lightroom compatibility boundary

Adobe's public Camera Raw namespace reference does not document the modern mask structures needed by #147. Treat compatibility as an empirical claim based on real fixtures and application round-trips.

Compatible

Only proven overlap

Brush, linear, radial, operations, local adjustments, multiple masks, and stable IDs enter the supported set only after real Lightroom import and export succeeds.

Preserved

Unknown stays opaque

Unknown groups, range masks, unsupported nesting, AI payloads, and future properties remain in opaque XML and the lossless Darkroom payload.

Save choice

Lossless or compatible

Darkroom lossless retains all Darkroom state. Lightroom compatible adds only verified structures and previews reduced, preserved-only, or rejected components.

Library query and controlled viewer rules

Read this section before Steps 7 and 8. These rules prevent grid and viewer drift and keep dual-pane interactions from changing the wrong asset.

interface LibraryQuery {
  version: 1;
  source: AllSource | FolderSource | AlbumSource | ArchiveSource;
  text: string;
  format: "all" | "raw" | "standard";
  curation: CurationFilter;
  facets: MetadataFacets;
  sort: {
    field: "name" | "capture-time" | "rating" | "pick";
    direction: "asc" | "desc";
  };
}

interface ViewerSession {
  version: 1;
  query: LibraryQuery;
  orderedIds: readonly AssetId[];
  catalogRevision: number;
  activeId: AssetId;
  origin: {
    selectedIds: readonly AssetId[];
    focusedId: AssetId;
    scrollAnchor: AssetId | null;
  };
  mode: ViewerMode;
}

Query and route

  • One pure selector applies source, archive policy, search, metadata facets, format, curation, sort, direction, and deterministic ties.
  • Search covers filename, title, caption, copyright, keywords, camera, and lens. Metadata facets cover camera, lens, capture year, metadata status, and conflict status.
  • The grid creates a versioned session before routing. The route carries active ID and short session ID, not the result set.
  • After a settled mutation, recompute and rebase. Choose the nearest survivor from the prior order if active becomes ineligible.

Return and restart

  • Returning in the same app session restores query, selection, focused asset, and virtual-grid scroll anchor.
  • An empty result returns to the library with the query intact and an empty-state message.
  • Renderer reload may restore a valid session. A direct or stale route rebuilds from the last root-scoped query, then falls back safely and states that context was rebuilt.
  • Layout preferences may persist. Reference identity clears on full app restart.

Rollout and rollback

  • Land foundation code inactive, then enable read-only extraction and sidebar first.

  • Retain the v2 catalog backup until successful v3 reopen and clean shutdown. Never downgrade a v3 catalog in place.
